# FLOWVISION v1.0.7 — physical field test checklist

Specification §25. This is a one-time upgrade-and-sensor-fusion verification
for this specific build (`versionName 1.0.7`, `versionCode 8`), separate from
the FIELD-GATE.md 20-consecutive-run gate. **Automated tests, Expo export, and
a Gradle build passing prove none of this** — every item below requires a real
Android phone. Do not resume Live Flow development until this checklist and
FIELD-GATE.md both pass on a physical device.

## Before you start

- Have the currently-installed field build (`versionCode 7`) on the test
  phone, with at least one real Site and one real saved Measurement already
  in it.
- Install the new APK **over** the existing app (do not uninstall first).

## The 20 items

| # | Step | Pass condition |
|---|------|-----------------|
| 1 | Install the new APK over versionCode 7 | Installs as an update — Android does not ask to uninstall first; no "app not installed" error |
| 2 | Open the app immediately after the update | Launches straight to the app's normal screen, not a crash or blank screen |
| 3 | Open Sites | Every Site created under the old build is still there, unchanged |
| 4 | Open a saved Measurement created under the old build | Opens and displays its original numbers; nothing recalculates or disappears |
| 5 | NEW MEASUREMENT → choose an existing Site | Site geometry loads; depth is empty and asks to be measured, exactly as before |
| 6 | Velocity → Video → open VIDEO VELOCITY, grant camera permission | Camera preview appears; no blank screen at any point |
| 7 | Record a clip | Video is written to permanent app storage; stored size is displayed and greater than 0 |
| 8 | Place ROI points 1–4, set flow direction, enter the known width and length | Calibration status reads VALID; the ROI's flow-direction control is visible and changes the saved value |
| 9 | Run the SSIV analysis | Returns Vsurface, streamwise/lateral velocity, cross-flow ratio, and accepted/total vectors — or one of the named failure categories with a corrective action |
| 10 | Save the measurement, leave the screen, reopen it | The record is present after reopening, with the same numbers |
| 11 | Open the saved record's TECHNICAL DATA section | A `SensorSnapshot` is present: device model, camera resolution, timing source, Δt |
| 12 | Check pitch/roll in TECHNICAL DATA | Values are plausible for however the phone was actually held (a phone held level reads near 0°, held tilted reads a correspondingly larger angle) |
| 13 | Deliberately move/shake the phone during a second recording | The angular-motion RMS (gyro-derived) and acceleration RMS values visibly increase versus a steady-handed recording |
| 14 | Record once in a dim room or shadowed area | Image quality reports a reason such as "VIDEO TOO DARK" or a visibly lower brightness/contrast value than a well-lit recording |
| 15 | Record once with a light source reflecting directly off the water | The glare score is visibly higher than in a glare-free recording |
| 16 | Turn off / deny GPS, and (if possible) disable other optional sensors, then complete a full measurement | The measurement still completes and saves; unavailable sensors show as UNAVAILABLE, never as 0 or a guessed value, and nothing blocks the save |
| 17 | Camera-assisted level: mark 8–12 rim points, then adjust the draggable water line (drag it, use the rotation handle, pinch to zoom) | The depth reading updates live as the line moves; Undo restores the previous line position; Reset returns it to the auto-suggested line |
| 18 | Export PDF from a saved measurement | File is produced locally and reaches the chosen folder through the Android system chooser / SAF |
| 19 | Export CSV from the same measurement | File is produced locally the same way; open it and confirm new columns (streamwise/lateral velocity, cross-flow ratio, timing source, Δt) are present and not blank where evidence exists |
| 20 | Fully close the app (remove from recent apps) and reopen it | All Sites, Measurements, calibration points and Settings are exactly as they were — nothing was lost by the restart |

## Recording the result

Log each run the same way FIELD-GATE.md does: date, device, Android version,
outcome, notes. A failure on any item is a blocker for this release — fix the
cause and restart the checklist from item 1, not from the failed item, since
an early step's failure can mask what a later step would have shown.

## What this checklist does not cover

- It does not establish measurement *accuracy* against an independent
  reference discharge — that is the validation-dataset work (specification
  §18/§20), a separate and much longer process.
- It does not exercise Live Flow (BETA, paused).
- A pass here is a claim that the app **works** on a real device after the
  upgrade — not that its numbers are metrologically validated.
